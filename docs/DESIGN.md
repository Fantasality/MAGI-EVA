## 二、EVA 界面语法

这套颜色不是装饰，而是一套**语法**——它规定了屏幕上每一种颜色可以有、以及不可以有的含义：

- **纯黑是「活动的虚空」。** 界面底色取纯黑，不是因为它中性，而是因为 EVA 的控制台永远建立在「空」之上：屏幕先是黑的，然后信息才被点亮。误差的填充也是纯黑——一台没有读数的子系统，在视觉上等同于没有被点亮，与背景同为一物。
- **三色构成一组交通信号式的层级。**
  - **绿 = 信息 / 已计算**：荧光绿（`#52E691`）只在三贤人一致放行时出现，是「机器已经算完了、结论成立」的颜色；
  - **橙 = 机器自身的机体与注意力**：主橙（`#FF8D00`）是这条界面的皮肤——边框、标题、贤人块底色、页眉的机读标记都用它。它是 MAGI 在「看着你」的颜色，而非结论的颜色；
  - **红 = 已被承认的危险**：血红（`#A41413`）专用与否决。它一旦出现，就代表某位贤人已经行使了否决权。
  三者之上，蓝（情报）与灰（误差）分列两侧：蓝表示「这不是一个可否决的问题」，灰表示「有子系统没能作答」。
- **等宽终端的排版。** 所有读数——延迟、token、概率分布、确信分——一律使用等宽字体，按列对齐。这既是可读性的要求，也是设定上的姿态：MAGI 吐给你的是**终端输出**，不是排版好的散文。
- **紧密咬合的模块网格。** 面板不是并排摆放，而是像插接的机体装甲一样互相咬边、共享边界。界面的每一块都被网格的分数坐标钉死，没有一块是浮动的。
- **危险斜纹（hazard chevron）。** 警示区使用工业标识的斜纹图案；本作中「状態」的填充也采用双色斜纹，正是把「此结论带条件、未获全数放行」按危险语义来编码。

## 三、布局：MAGI 网格

整个控制台建立在一张分数网格上。坐标以内容盒为基准：

**列（内容盒宽度的分数）**

```
LX0 = 0.0        LX1 = 0.33333     LX2 = 0.41667
LX3 = 0.58333    LX4 = 0.66667     LX5 = 1.0
```

**行（内容盒高度的分数）**

```
RY0 = 0.0        RY1 = 0.25        RY2 = 0.5
RY3 = 0.625      RY4 = 1.0
```

各区域在网格上的占位。**每个区域都由 CSS 的命名网格线推导而来**——为避免差一位，先给出线号对应表：

| CSS 命名线 | 本工程索引 |
| --- | --- |
| `grid-row/column` 起始线 | — |
| `casper-start` / `status`（第 2 条列线） | `LX0` |
| `left-header-end` / `balthasar-start`（第 3 条） | `LX1` |
| `casper-end` / `title`（第 4 条） | `LX2` |
| `melchior-start`（第 5 条） | `LX3` |
| `balthasar-end` / `response`（第 6 条） | `LX4` |
| `melchior-end`（第 7 条） | `LX5` |
| `header` / `balthasar-start`（第 2 条行线） | `RY0` |
| `status` / `response`（第 3 条） | `RY1` |
| `casper-start` / `melchior-start`（第 4 条） | `RY2` |
| `balthasar-end` / `title`（第 5 条） | `RY3` |
| `casper-end` / `melchior-end`（第 6 条） | `RY4` |

| 区域 | 列 | 行 |
| --- | --- | --- |
| 頁眉 質 問 | 左内缘→`LX1` | `RY0`→`RY1` |
| 頁眉 解 決 | `LX4`→右内缘 | `RY0`→`RY1` |
| 状态读数 | `LX0`→`LX1` | `RY1`→`RY2` |
| CASPER • 3 | `LX0`→`LX2` | `RY2`→`RY4` |
| BALTHASAR • 2 | `LX1`→`LX4` | `RY0`→`RY3` |
| MELCHIOR • 1 | `LX3`→`LX5` | `RY3`→`RY4` |
| 标题 MAGI | `LX2`→`LX3` | `RY3`→`RY4` |
| 结论框 | `LX4`→`LX5` | `RY1`→`RY2`（右对齐、垂直居中） |

三处容易搞错、值得单独记下：

1. **状态读数占的是左侧整根 2fr 宽的列**（`LX0`→`LX1`），不是窄格。`status` 这个名字同时出现在第 2 条列线与第 3 条行线上，按 CSS「起止同名线＝跨一条轨道」的规则，它覆盖的是那条 2fr 列的一条轨道高。
2. **两个页眉都吃进了 20dp 装订边**：`left-header-start` 是整张网格的第 1 条线，所以 質 問 从容器左内缘（含装订边）起算；解 決 同理止于右内缘。
3. **BALTHASAR 从 `LX1` 起、不是 `LX2`**。它是唯一同时跨三行、又横跨到第 6 条列线的块，起点偏一位就会和 CASPER 之间露出缝隙。

注意 BALTHASAR 的块从 **RY0 起**、MELCHIOR 落在 **RY3→RY4**、CASPER 压在左下、标题 MAGI 插在中央——四个不等高的块沿对角方向彼此咬合，而不是上下分栏。

## 四、三个贤人块的裁形

每个贤人块都不是矩形，而是以各自块的百分比坐标裁切（`clip-path` 语义）：

- **MELCHIOR • 1**
  ```css
  polygon(35% 0, 100% 0, 100% 100%, 0 100%, 0 44%)
  ```
- **BALTHASAR • 2**
  ```css
  polygon(0 0, 100% 0, 100% 80%, 75% 100%, 25% 100%, 0 80%)
  ```
- **CASPER • 3**
  ```css
  polygon(0 0, 65% 0, 100% 44%, 100% 100%, 0 100%)
  ```

这三组裁形**互相咬合**，在屏幕上拼出动画里那块沿对角线排列的**三体结构**：MELCHIOR 切掉左上角、CASPER 切掉右上角、BALTHASAR 切掉下面两个角，边缘彼此让位、不留缝隙。

三块之间的**连接条**随之旋转，角度分别为 **−54° / 0° / +54°**——它们把三贤人的对角线排布在视觉上焊接成一体，指示「这是一台机器，不是三个软件」。

## 五、状态的两种非平涂填充

五种结论里，只有两种不是纯色平涂：

- **状態**：**56° 双色绿斜纹**，由 `#52E691`（荧光绿）与 `#82CD68`（浅绿）交替构成。斜纹本身即「带条件、未获全数放行」的视觉隐喻——它有绿的形状，却没有绿的纯度。
- **誤差**：**纯黑**填充。如前所述，纯黑在此不是「缺少颜色」，而是「没有被点亮」。一台没能给出读数的子系统，与背景同色。

其余三种（合意、拒絶、情報）均为对应主色的平涂。

## 六、字体

| 用途 | 字体 | 来源 |
| --- | --- | --- |
| 显示字体 | **FOT-Matisse Pro ExtraBold** | `assets/fonts/MatisseEB.otf`（约 9.8 MB，装载一次后全程复用） |
| 终端读数 | 系统 **monospace** | Android 上为 Roboto Mono / Droid Sans Mono，与参考实现的 Lucida Console 气质一致 |

显示字体只用于标题、贤人代号与結论文案；所有数值与机读字段一律走等宽。字体若装载失败，必须回退到系统衬线／等宽——**绝不能让字体缺失导致整块面板画不出来**。

### 字号：以面板高度为基准（cqh）

参考实现把字号写成 `cqh`——**容器高度的 1%**，而它用 `container-type: size` 把容器指定为 `.magi` 面板本身，所以基准是**面板高度**，不是文字所在那个格子高度。这一条极易搞错：把 `8cqh` 误当成「所在块高度的 8%」会让所有字号系统性偏小几倍。

对应到本工程，基准是 View 高度 `h`：

| 元素 | 参考值 | 实现 |
| --- | --- | --- |
| 页眉 質 問 / 解 決 | `10cqh` | `0.10 × h`，夹在 10sp–26sp |
| 贤人代号 | `8cqh` | `0.08 × h`，夹在 11sp–30sp |
| 标题 MAGI | `9cqh` | `0.09 × h`，夹在 14sp–46sp |
| 状态读数首行 | `6cqh` | `0.06 × h`，下限 10dp |
| 状态读数其余行 | `3cqh` | `0.03 × h`，**下限 7dp** |

### 唯一一处自觉偏离：状态读数的可读下限

参考实现的面板按 1200×600 px 布局，`3cqh` ≈ 18px，清楚易读。手机竖屏下面板宽度约 380dp、高度仅约 190dp，`3cqh` 只有 **5.7dp**——比 1 号字还小，实际读不出来。因此状态读数的小字设了 **7dp 下限**。

这是全工程对参考实现的**唯一一处有意偏离**，且只在「面板高度 < 约 230dp」时才会触发；横屏或平板上面板变高，字号即回到纯 `cqh`。取此折中是因为：状态读数是**有信息量的机读字段**（`EXTENTION` 会随闸门结果在 `????` / `7312` / `3023` 之间变化），不是装饰。若追求零偏离，把下限改成 0 即可，代码中已注明位置。

## 七、动效

- **闪烁（flicker）**：`0.25s` 的 **step-end 无限循环**——硬切，不做渐变。
- 闪烁**只在对该贤人的计算尚未返回时开启**：位仍在「计算中」的贤人块闪，读数已到的块即停。
- **不伪造进度条。** 界面不显示任何百分比推进的进度条；未被返回的计算只有「闪」与「不闪」两态，绝不用动画假装知道背后的进度。
